# fluxos v1.0.0-rc1 release notes

**Status:** release candidate in preparation. This document does not announce a publication.

## Platform and build policy

The qualification scope covers only a native `linux/amd64` build with CGO enabled and GCC.
Ubuntu 24.04 x64 is the baseline for that scope. Builds on another Linux distribution can be run
with `--diagnostic`, but their result is diagnostic evidence only.

The repository must be a clean Git checkout. The verifier normalizes the relevant Go and CGO
environment, performs two builds on the same host with independent temporary `GOCACHE`
directories, and compares the resulting Linux/amd64 binaries byte for byte. This proves only
same-host build repeatability; it does not qualify the RC or establish reproducibility across
different installations or toolchains.

## Generating an artifact outside the checkout

From a clean checkout on the Ubuntu baseline, use a new or empty directory outside the Git
worktree:

```bash
./scripts/verify-reproducible-build.sh \
  --output-dir /tmp/fluxos-v1.0.0-rc1 \
  v1.0.0-rc1
```

For a non-baseline host such as Arch Linux, add `--diagnostic`. The output directory is not a
release repository: it is temporary local evidence and must remain outside the checkout. The
verifier promotes output only after both builds are byte-identical and both `--version` checks
pass. It does not copy caches, the checkout, or intermediate binaries into the repository.

The output contains:

- `fluxos-v1.0.0-rc1-linux-amd64`, the single promoted executable;
- `SHA256SUMS`, containing the SHA-256 and stable base name of that executable; and
- `BUILD_INFO.txt`, containing the source commit, version, host qualification, host, Go/GCC/linker,
  build flags, normalized environment, and artifact SHA-256.

The metadata labels the host as `ubuntu-24.04-baseline` or `diagnostic`, records the OS ID and
version, uses verification scope `same-host build repeatability only`, and sets `rc gate: not
evaluated`.

`SHA256SUMS` records the digest used to verify the bytes of the generated artifact; it is not a
signature and does not identify a published download. `BUILD_INFO.txt` describes how the local
evidence was produced. No concrete checksum is recorded in these notes.

## Release-candidate smoke and gate

The smoke interface consumes only a promoted bundle and is run without Maven:

```bash
./scripts/smoke-release-candidate.sh \
  v1.0.0-rc1 \
  /tmp/fluxos-v1.0.0-rc1
```

It checks `SHA256SUMS`, `BUILD_INFO.txt`, `--version`, and byte-for-byte fixture outputs for:

- M3 `Workflow.start`;
- M4 default `--no-prompt`, `--all-impls`, and
  `--pick-impls=contracts.A=app.AlphaA,contracts.B=app.GammaB`;
- JSON and DOT in `testdata/m4/runtime-context`; and
- Spring Petclinic, cloned temporarily from
  `https://github.com/spring-projects/spring-petclinic.git` at detached commit
  `c36452a2c34443ae26b4ecbba4f149906af14717`, targeting
  `org.springframework.samples.petclinic.owner.OwnerController.processFindForm`.

The gate interface runs the local test, race, vet, reproducible-build, and smoke checks:

```bash
./scripts/verify-release-candidate.sh \
  --diagnostic \
  v1.0.0-rc1 \
  /tmp/fluxos-v1.0.0-rc1
```

On local success it prints `local gate: passed`, then `remote CI: pending` and
`result: pending-remote-ci`, and exits with status 3. A pending gate is not RC approval,
qualification, publication, or a substitute for an observed green remote CI execution. If the
network is unavailable, the Petclinic smoke fails rather than inventing evidence.

## Open blockers

- The GitHub Actions workflow exists, but no remote green execution has been observed.
- The Ubuntu 24.04 x64 baseline has not established RC qualification here; an Arch or other
  non-baseline run remains diagnostic only.
- No tag, remote release, or publication is promised by this release candidate.
